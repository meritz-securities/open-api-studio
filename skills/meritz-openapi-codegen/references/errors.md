# 응답 코드와 대응

## 먼저 알아둘 두 가지

**이 게이트웨이는 오류를 종류와 무관하게 HTTP 500 으로 낸다.**
권한이 없어도 500, 필수값이 빠져도 500, 날짜가 뒤집혀도 500 이다. 403·400 은 오지 않는다.
**상태코드로 가르지 말고 본문의 `rsp_cd` 를 읽는다.**

**무엇을 고쳐야 하는지는 `rsp_sub_msg` 에 있다.**
`rsp_msg` 는 두루뭉술하고, 실제 조치 정보는 따로 온다. 사용자에게 함께 전한다.

| `rsp_cd` | `rsp_msg` | `rsp_sub_msg` |
|---|---|---|
| `7936` | 해당데이터가 없습니다. | `조회시작일` ← 어느 항목이 빠졌는지 |
| `0760` | 권한이 없습니다. | `계좌 관리점과 직원소속부서 확인!!` ← 무엇을 해야 하는지 |
| `5820` | 조회할 내역(자료)이 없습니다. | `종료일자보다 클 수 없습니다.` ← 왜 0건인지 |

## 판정 순서

```
1) 본문을 JSON 으로 읽는다             HTTP 상태코드로 가르지 않는다
2) 주문이면 data.warn_cls_code 부터    경고면 접수되지 않았다
3) rsp_cd 를 읽을 수 있는가
     성공 코드면 성공, 아니면 업무 오류
4) 읽을 수 없다면 알려진 손상 API 인지 확인 (corrections.md)
5) 자료 유무는 rsp_cd 가 아니라 data 로 판정한다
6) 오류면 rsp_sub_msg 를 함께 전한다
```

## 성공으로 보는 코드

| 코드 | 뜻 | 주의 |
|---|---|---|
| `0000` | 정상 | |
| `0001` | 주문 접수 | **체결이 아니다.** `warn_cls_code` 를 함께 본다 |
| `5762` | 다음 페이지 있음 | 오류가 아니다. `tr_cont` 로 이어 조회 |
| `5766` | 정상 | |
| `5820` | 조회할 자료 없음 | **자료가 있어도 온다.** 아래 절을 읽는다 |
| `5822` | 조회할 자료 없음 | 입출금 계열. `5820` 과 같은 주의가 필요하다 |
| `00000` | 실시간 구독 성공 | 5자리다. REST 의 `0000` 과 다르다 |

### `5820` 을 "자료 없음" 으로 단정하지 않는다

이 게이트웨이는 **자료를 담은 채로도 `5820` 을 보낸다.** 해당 API 는 다음과 같습니다.

| API | 응답 |
|---|---|
| `collateral` (담보) | `rsp_cd` `5820` · `data` 에 총자산이 들어 있다 |
| `profit_loss_symbols` (종목별 실현손익) | `rsp_cd` `5820` · `data` 9행 |
| `ovs_profit_loss` (해외 실현손익) | `rsp_cd` `5820` · `data` 와 `summary` 가 함께 온다 |

다른 API 도 같을 수 있다. **자료 유무는 응답코드가 아니라 `data` 가 비었는지로 가른다.**
`rsp_cd == "5820"` 이라는 이유로 "거래 내역이 없습니다" 라고 답하면
사용자의 실제 자료를 통째로 버리는 것이다.

## 주문이 접수되지 않는 경우

응답에 `warn_cls_code` 가 있고 그 값이 `0` 이 아니면 **주문이 접수되지 않은 것이다.**
`rsp_cd` 가 `0001` 이고 "주문이 완료되었습니다" 여도 마찬가지다.
목록을 외우지 않는다 — **`0` 만 접수, 나머지는 전부 미접수다.**

```python
code = str(row.get("warn_cls_code", "")).strip()
if code and code != "0":
    ...  # 접수되지 않았다
```

미접수는 두 갈래이고, 갈래는 국내와 해외가 다르다.
**국내와 해외는 코드 체계가 달라 값을 공용으로 쓰지 않는다.**

| | 국내 주문 | 해외 주문 |
|---|---|---|
| 재전송으로 풀림 | `1`·`3`·`4`·`6`·`7`·`9`·`a`·`c`·`d`·`f`·`g` | `1`(경고)·`3`(미국 PTP 과세 확인) |
| 재전송으로 안 풀림 | 그 밖의 값 (`2`·`5`·`8`·`b`·`e`·`h` 등) | 그 밖의 값 (`2` 등) |

재전송으로 풀리는 값이면, 경고 문구를 사용자에게 보이고 동의를 받은 뒤 같은 주문에
`warn_cnfr_yn=Y` 를 더해 다시 보내야 접수된다. **동의 없이 재전송하지 않는다.**
그 밖의 값은 거절·보류라 다시 보내도 접수되지 않는다 — `warn_msg` 로 사유를 확인한다.

이 검사를 `rsp_cd` 성공 판정보다 **먼저** 둔다. 뒤에 두면 영영 안 걸린다.

## 오류 코드

**전부 HTTP 500 으로 온다** (`EGW00103` 만 403 으로 올 때가 있다).

| 코드 | 뜻 | 대응 |
|---|---|---|
| `0760` | 권한 없음 | 앱키·계좌에 그 API 권한이 없다. **재시도·토큰 재발급으로 풀리지 않는다.** 포털에서 권한을 신청한다. `rsp_sub_msg` 에 안내가 함께 온다 |
| `3174` | 시작일이 종료일보다 큼 | 두 날짜가 바뀌었다 |
| `3176` | 시작일자를 확인하십시오 | 시작일자가 없거나 허용 범위를 벗어났다 |
| `3180` | 시장가·최유리에 단가를 넣음 | `oder_unpr=0` 으로 다시 보낸다 |
| `5018` | 입력값이 목록에 없음 | 한 바이트 이하 코드값이다. 허용 코드값을 확인한다 |
| `5806` | 거래소 벤더코드 오류 | 거래소 코드 체계가 API 마다 다르다 — 시세는 `OQ`, 주문·잔고는 `0537` |
| `6102` | 일자 형식 오류 | `YYYYMMDD` 여덟 자리. 하이픈이 섞이면 `IGW50004` 가 오기도 한다 |
| `7668` | 적용환율을 조회할 수 없는 통화 | `rsp_msg` 는 "필수 입력 항목이 누락되었습니다.", `rsp_sub_msg` 는 `연계기관코드` 로 오지만 **입력 누락이 아니라 통화 문제**다 |
| `7936` | 필수 입력 누락 | `rsp_msg` 는 "해당데이터가 없습니다." 로 온다. **자료 없음이 아니다.** 어느 항목인지는 `rsp_sub_msg` 에 있다 |
| `IGW50004` | 전문 길이 초과 · 필수 누락 | 값의 자릿수가 명세보다 길거나 필수 파라미터가 빠졌다. `corrections.md` 확인 |
| `IGW50006` | 시장구분코드가 그 API 에 맞지 않음 | `mrkt_div_code`·`mrkt_cls_code` 를 그 API 설명에서 다시 확인한다 |
| `IGW50024` | 필수 헤더 누락 | `mac_address` 헤더를 12자리 대문자 16진수로 넣는다 |
| `EGW00002` | 서버측 오류 | 자격증명 문제가 아니다. 앱키를 다시 묻지 않는다 |
| `EGW00103` | 유효하지 않은 `client_id` | 앱키 오타, 또는 **개발 앱키를 운영 서버에 쓴 경우**다. 재발급으로 풀리지 않는다 |
| `EGW00121` | 유효하지 않은 token | 토큰을 새로 받는다. `meritz` CLI 는 자동으로 재발급해 한 번 재시도한다 |
| `EGW00123` | 기간이 만료된 token | 캐시의 만료 시각이 남아 있어도 서버가 거절한다. 재발급한다 |
| `EGW00200` | 초당 호출 한도 초과 | 재시도 가능하다. API 당 초당 10건 |
| `EGW00202` | 권한 없음 (게이트웨이 단계) | 실제로는 `0760` 으로 오는 경우가 더 많다 |
| `WSC00106` | 실시간 미개방 | 해당 서버에서 그 구독이 열려 있지 않다 |
| `WSC00108` | 구독 요청 오류 | `tr_cd`·`tr_key` 형식 확인 |
| `WSC00110` | 계정당 최대 세션 수 초과 | 같은 앱키로 열어 둔 웹소켓을 먼저 닫는다 |

## 오류가 아닌데 조용히 어긋나는 것

응답 코드가 정상인데 결과가 틀린 경우다. 코드로는 잡히지 않는다.

- **날짜 형식** — `from`·`to`·`*_date` 가 8자리가 아니면 오류 없이 **기간이 무시된**
  자료가 정상 코드와 함께 온다. `market_investors` 는 `from` 이 8자리가 아니면 2년치
  655건이, `to` 가 8자리가 아니면 0건이 온다
- **거래소 코드 혼용** — 잔고는 `0537`(벤더 코드), 실현손익은 `OQ`(거래소 코드)다.
  바꿔 넣으면 오류 없이 0건이 온다
- **연속조회 키 훼손** — `tr_cont_key` 는 오른쪽에 공백이 붙어 온다. 잘라내면 다른
  구간을 받거나 같은 페이지를 무한 반복한다. 연속조회가 실제로 동작하는 API 는
  `transactions` · `orders_history` · `ovs_orders_history` · `ref_ovs_exchanges` 네 건뿐이다

## rsp_cd 가 깨져 오는 API

국내 시세 일부는 `rsp_cd` 에 제어문자가 섞여 온다. **데이터 자체는 정상**이다.
대상은 `corrections.md` 에 있다.

이 경우 업무 성공 여부를 코드로 판정할 수 없다. 결과를 전할 때
**"응답 코드가 확인되지 않았다"는 점을 밝힌다.** 깨진 값을 의미 있는
코드인 것처럼 설명하지 않는다.

목록에 없는 API 에서 코드가 깨져 오면 **성공으로 처리하지 않는다.**
모르는 손상을 통과시키면 실패가 성공으로 보고된다.
