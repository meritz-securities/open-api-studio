# 메리츠증권 Open API — 조회와 주문

`meritz` CLI 로 **실제 호출**한다. 코드를 짜지 않는다.

이 스킬은 **실제 계좌에 영향을 준다.** 아래 규칙은 예외가 없다.

## 첫 호출 전 1회

```bash
meritz doctor
```

서버·자격증명·카탈로그를 한 번에 보여준다. 자격증명이 없으면
`references/setup.md` 를 읽고 안내한다. **호출을 먼저 시도하지 않는다.**

`meritz doctor` 는 기본이 **운영 서버**다. 다른 서버로 붙이려면
`MERITZ_BASE_URL` 과 `MERITZ_WS_URL` 을 **둘 다** 지정한다. 하나만 바꾸면
토큰은 옮긴 서버에서 받고 구독은 운영으로 나간다.

## 작업 순서

1. **의도 파악** — 조회인가, 상태를 바꾸는가
2. **API 찾기** — `meritz api list -q <키워드>` (한글로 물어도 된다)
3. **명세 확인** — `meritz api show <api_type>`. **파라미터를 추측하지 않는다**
4. **실행** — 조회는 `meritz call`, 주문·환전은 `meritz order`
5. **해석** — 응답은 영문 약어다. `references/glossary.md` 로 한글명을 붙인다

| 파일 | 언제 읽나 |
|---|---|
| `references/setup.md` | 설치·앱키·서버 설정 |
| `references/corrections.md` | **포털 명세가 실제와 다른 곳. 시세 호출 전에 본다** |
| `references/errors.md` | 오류코드 해석 |
| `references/api-catalog.md` | 75건 전체 목록 |
| `references/glossary.md` | 응답 필드 한/영 |

## 어떤 조회인지 먼저 가른다

"잔고" 라는 한 단어가 네 가지를 뜻할 수 있다. 무엇을 묻는지 애매하면 되묻는다.

| 사용자가 말한 것 | 부를 것 |
|---|---|
| 총자산·평가금액 | `valuation` |
| 종목별 보유·평가손익 | `holdings` |
| 현금·출금가능·주문가능 | `deposit` |
| 해외 보유 / 외화 잔고 | `ovs_holdings` / `ovs_currencies` |

## 장 시간을 먼저 본다

개장 전에는 누적거래량이 0 이고 시가·고가·저가가 기준가와 같다.
그 값을 "현재가" 라고 말하면 오해를 부른다. **"개장 전이라 전일 종가 수준" 이라고 밝힌다.**

| 구분 | 시간 |
|---|---|
| 정규장 | 09:00–15:30 |
| 장전 시간외 | 08:30–08:40 |
| 장후 시간외 | 15:40–16:00 |
| 시간외 단일가 | 16:00–18:00 |

실시간 구독이 조용하면 종목코드보다 **장 시간을 먼저** 의심한다.

## 조회

```bash
meritz call deposit
meritz call market_prices -p mrkt_div_code=J -p iscd=005930
meritz api show market_prices        # 필수 항목이 헷갈리면 먼저 이것부터
```

- **계좌 파라미터(`acno`·`asno`·`acnt_pwd`)는 넣지 않는다.** 앱키에 계좌가
  묶여 있어 값을 채우면 실패한다.
- **종목코드 형식이 API 마다 다르다.** 시세는 `005930`, 주문은 `A005930`(앞에 `A`).
  헷갈리면 `meritz api show` 로 그 API 의 예시를 확인한다.
- 명세에 없는 파라미터는 CLI 가 거부한다. 이름을 지어내지 않는다.
- 성공 판정은 CLI 가 한다. `rsp_cd` 를 눈으로 보고 판단하지 않는다.
- **연속조회는 4건에서만 동작한다** — `transactions`(입출금 내역)·`orders_history`
  (국내 주문내역)·`ovs_orders_history`(해외 주문체결내역)·`ref_ovs_exchanges`
  (해외 거래소 목록). 이 4건은 응답에 `tr_cont_key` 가 오면
  `--tr-cont 1 --tr-cont-key <값>` 으로 이어 조회한다. `rsp_cd` 가 `5762` 인 동안
  반복하고, `5766`·`5820`·`5822` 면 끝이다.
- **그 밖의 API 에는 연속조회를 걸지 않는다.** 카탈로그에 `tr_cont`/`tr_cont_key`
  를 선언한 API 는 더 많지만, 실제로 다음 구간이 오는 것은 위 4건뿐이다. 나머지는
  같은 구간을 반복하거나 거짓 0건을 준다. **`meritz call` 은 이것을 막지 않는다** —
  화이트리스트(`PAGING_OK`)는 라이브러리의 `paginate()` 안에만 있고 CLI 는 `--tr-cont`
  를 그대로 전달한다. 4건 밖에서 쓰면 중복된 행을 진짜 데이터로 착각하게 되므로,
  막아 주는 장치가 없다고 보고 쓰지 않는다.
- 종료코드 `0` 성공 / `2` 사용법 / `3` 실패 / `4` 확인 필요(미리보기·확인 거부 양쪽) /
  `5` 주문 미접수.
- **`MERITZ_READ_ONLY` 기본값은 `1` 이다 — 조회 전용으로 시작한다.** 사용자가
  `0` 으로 열어 두지 않았다면 주문·환전을 시도하지 않는다. 그 값을 스스로
  바꾸거나 우회하지 않는다.

## 주문·환전 — 확인 게이트

게이트는 `ApiClient.call()` 안에 있다. `meritz` 명령으로 내든 파이썬에서 직접
부르든 유효한 토큰 없이는 전송되지 않는다. 토큰 발급·폐기(`oauth2_token`·
`oauth2_revoke`)만 제외인데, 폐기는 진행 중인 세션을 전부 끊으므로 확인 없이
부르지 않는다.

`meritz api list --state-changing` 이 대상 전부를 보여준다.

**1단계 — 미리보기.** `--confirm` 없이 실행하면 **전송하지 않고** 보낼 내용과
토큰만 보여준다.

```bash
meritz order orders_buy -p iscd=A005930 -p odqt=1 -p oder_unpr=50000 ...
```

이 출력을 **줄이거나 요약하지 말고 그대로 사용자에게 보여주고** 종목·수량·가격을
확인받는다.

**2단계 — 사용자가 동의한 뒤에만** 토큰을 붙여 다시 실행한다.

```bash
meritz order orders_buy -p ... --confirm <토큰>
```

토큰은 **1회용이고 180초**다. 요청 값이나 **대상 서버**가 바뀌면 무효가 된다 —
그때는 미리보기부터 다시 한다. 미리보기를 다른 서버로 띄우고 전송만 운영에서
하는 것은 막혀 있다.

### 하지 말 것

- 사용자 동의 없이 `--confirm` 을 붙이지 않는다. "주문해줘" 는 동의가 아니다
- 사용자가 말하지 않은 종목·수량·가격을 채우지 않는다. **빠진 값은 물어본다**
- `exch_kind_code`(01 KRX · 02 NXT · 03 SOR)도 사용자가 말하지 않았으면 물어본다.
  체결 가격이 달라진다. 임의로 채우지 않는다
- 여러 주문을 한 번에 묶지 않는다. 한 건씩 미리보기 → 확인 → 전송
- 미리보기 출력을 요약하지 않는다

### 해외는 종목코드 형식이 세 군데 다 다르다

| 어디 | 형식 |
|---|---|
| 시세 | `AAPL` + `mrkt_cls_code=OQ` |
| 주문 | `AAPL` + `ovrs_exch_vndr_idno` (거래소 번호) |
| 잔고 | `AAPL.OQ` |

**잔고에서 본 `AAPL.OQ` 를 그대로 주문에 넣지 않는다.**
거래소 번호는 `ref_ovs_exchanges` 에서 `onln_yn="Y"` 인 것만 쓸 수 있다.

### 접수됐다고 끝이 아니다

주문 응답이 성공(`rsp_cd`=`0001`)이어도, `warn_cls_code` 가 **`"0"` 이 아니면
접수되지 않은 상태**다. 그대로 두면 아무 일도 일어나지 않는다.

재전송으로 풀리는지는 국내와 해외가 다르다. **국내 목록을 해외에 쓰지 않는다.**

| | 재전송하면 접수 | 재전송해도 안 됨 |
|---|---|---|
| 국내 | `1·3·4·6·7·9·a·c·d·f·g` | `2·5·8·b·e·h` |
| 해외 | `1`(경고) · `3`(미국 PTP 과세 확인) | `2`(보류) |

CLI 가 이 경우를 **실패로 판정한다** — 종료코드 `5`, `--json` 에서는
`"error": "ORDER_NOT_ACCEPTED"`. 응답의 `resendable` 로 어느 쪽인지 알 수 있다.
성공으로 보고하면 안 된다.

재전송으로 풀리는 값이면, 경고 문구를 사용자에게 보이고 동의를 받은 뒤
같은 주문에 `-p warn_cnfr_yn=Y` 를 더해 다시 전송한다.
**동의 없이 자동으로 재전송하지 않는다.**
보류 값이면 재전송해도 소용없으니 사유를 해소한 뒤 새로 주문해야 한다.

`rsp_cd`=`0001` 은 접수 성공일 뿐 체결이 아니다. 최종 상태는 주문내역
조회로 확인한다.

### 환전은 미리보기까지만 한다

환전(`fx_exchanges`)은 **자금 이동**이다. 미리보기까지만 하고, 실행은 사용자가
직접 하도록 안내한다.

절차를 지키지 않으면 잘못된 환율로 돈이 나간다.

1. `fx_rates_applied` 로 **적용환율**을 조회한다
2. 그 응답의 `exrt_stnd_time` 과 적용환율을 **그대로** 실어 `fx_exchanges` 로 보낸다

| 방향 | `mnec_clcd` | `iqry_exrt` 에 넣을 값 |
|---|---|---|
| 외화 매수(원화 → 외화) | `1` | `tltr_aply_byrt` — 기준환율보다 **높은** 쪽 |
| 외화 매도(외화 → 원화) | `2` | `tltr_aply_slrt` — 기준환율보다 **낮은** 쪽 |

- **`fx_rates` 값을 환전에 쓰지 않는다.** 그쪽은 계좌와 무관한 공개 고시환율이라
  우대가 반영되지 않고, 같은 이름의 필드가 반대 뜻이다
- **엔화는 100엔당 고시다.** 원화 금액 = 외화금액 × 적용환율 ÷ 100
- 견적은 시간이 지나면 무효다. 오래됐으면 다시 조회한다

## 실시간

```bash
meritz ws ws_stck_cntg --tr-key 005930 --count 20
```

접속점은 하나이고 `tr_cd` 가 무엇을 받을지 정한다. 체결·주문 통보는 `--tr-key`
없이 구독한다 — 앱키에 묶인 사용자 것이 온다.

**서버는 종목코드를 검사하지 않는다.** 없는 종목도 구독은 성공하고 데이터만
오지 않는다. 조용하면 종목코드와 장 시간을 먼저 의심한다.

## 결과 해석

- 금액·수량은 단위를 밝힌다(원·주·USD)
- **응답에 없는 값을 추론해 채우지 않는다.** 없으면 "응답에 없음"이라고 말한다
- 빈 결과는 오류가 아니다. "자료 없음"이다
- **`rsp_cd` 로 자료 유무를 판정하지 않는다.** 담보·종목별 실현손익·해외 실현손익은
  자료를 담은 채로도 `5820`("조회할 자료 없음")을 보낸다. `data` 가 비었는지로 가른다.
  코드만 보고 "거래 내역이 없습니다" 라고 답하면 사용자의 실제 자료를 버리는 것이다
- 오류는 종류와 무관하게 HTTP 500 으로 온다. 조치 정보는 `rsp_msg` 가 아니라
  `rsp_sub_msg` 에 담기니 함께 전한다(`references/errors.md`)
- 일부 시세 API 는 `rsp_cd` 가 손상돼 온다(`references/corrections.md`).
  데이터는 정상이지만 **업무 성공은 검증되지 않은 상태**임을 밝힌다

## 개인정보·보안

- 잔고·자산·계좌번호는 민감정보다. 묻지 않은 계좌 조회를 먼저 하지 않는다
- 앱키·시크릿을 출력하거나 파일에 쓰지 않는다. 토큰도 앞 12자까지만
- 조회 결과를 사용자가 요청하지 않은 곳으로 전송·업로드하지 않는다
- **다만 조회 결과는 이미 이 에이전트를 구동하는 AI 서비스의 서버로 전송된다.**
  저장·보관은 해당 사업자 정책을 따른다. 사용자가 이를 모르는 눈치면 알린다
  ([DISCLAIMER.md](../../DISCLAIMER.md))

## 하지 말 것

- 명세에 없는 파라미터·경로·`tr_cd` 를 지어내지 않는다
- 투자 판단이나 매매 추천을 하지 않는다. 조회된 사실만 전한다
- 실패를 성공처럼 요약하지 않는다. 오류코드와 사유를 그대로 전한다
